# 噪声增强与训练步数对照 v1

2026-10-25，在增强模型训练与结果计算前固定。沿用NOISE_PROTOCOL.md（SHA256 `9007c85e8c135bf38616973ee249d27e196cc5e7d8bcc102b94e1f2d95ce6f42`）的信号、标签、SNR、四分支与固定受试者划分；该原协议和既有测试缓存保持不改。

新增干扰缓存只使用原六名训练受试者的3775个明确监督窗。对每个候选窗口以record_id、窗口原生起点、seed42的稳定SHA256选择两类×四SNR中的一个条件；选择先于监督mask筛选且不读取标签值。每个明确监督窗仅生成一个额外加噪副本，标签、身份和起止时间逐项复制。噪声仍按整录音连续生成，alpha/g按整段协议校准，不逐窗重抽或缩放。不为边界无明确标签窗增加监督目标。

缓存同时保存原窗口索引、合成种类、SNR、gain和来源摘要，训练入口必须验证所有来源都属于train、所有标签/时间都与原索引相符，新增3775行完整且每个原监督窗恰好一次。保存67维特征与真实32×100图，不写整夜混合WAV；训练数据不会进入Git。

增强原计划会把训练行从3775增加到7550，最大优化步数也约翻倍。为区分额外训练次数与加入噪声，增加一个**等训练行数的原始重复对照**：

- 原始CNN：既有冻结3775行结果，不重写。
- clean_duplicate：原始监督行额外重复一次，合计7550；通过增强缓存的原索引取回原始图，绝不用加噪图。
- noise_augmented：原始3775行加上3775个预先选定的加噪图，合计7550。

后两者采用完全相同的原索引顺序、seed42、模型结构、batch64、AdamW lr0.001/weight_decay0.0001、最多20epoch/patience5和FP32；仅训练输入数值不同。分别只拟合其训练行的标准化，类别权重只用其训练标签；验证仍用原未缩放明确标签窗，按相同Macro-F1严格提高选检查点、平分最早。每个模型记录实际epoch/优化步数，早停可能使最终步数不同；不因此宣称严格同算力因果实验。

评价仍对同两名测试受试者全窗口、原未缩放参考和固定八噪声条件四分支执行；模型选定后才计算测试，全部条件报告，不改阈值或滤波参数。将增强与clean_duplicate对照及原始CNN并列，RF作为既有参考，不自动增加未预注册RF调参。两人试点不足以证明跨人群/设备可靠。

这是在增强结果可见前增加的训练预算控制，由样本数量翻倍这个设计事实触发，不由增强模型的测试分数触发。实现/实际数据准备、训练与性能结果分别记录；本文件不代表这些步骤已经完成。
