# 公开数据主项目：目标、运行路径与验收

2026-10-26 用户明确调整：**公开数据足以构成完整 NightLab，手机本人录音和 Android 是可选 DLC。** 本文件与 DECISIONS.md 覆盖早期把真人文件视为最终阻塞的记录。

当前目标：仅依靠已批准的 PSG-Audio 十人声音与 SleepAccel 三十一人时序，交付可运行、可演示、实验真实且可复现的本地 AI 研究工作台；完成数据来源与许可、受试者划分、经典/深度对照、抗噪与失败分析、公开样本查看、安装复现与公开 Git 记录。个人设备、手表、舍友与 Android 真机均不作为主项目完成条件。

## 完整项目包含什么

| 主线 | 可验收成果 |
|---|---|
| 数据依据 | 官方版本/文件/许可/引用/摘要，原主候选时间冲突与更换依据；只用既有批准清单 |
| 声音研究 | 十人 6/2/2、RF/CNN、连续事件、合成干扰/滤波/增强及等训练量控制；保留负面结果 |
| 可穿戴研究 | 三十一人 18/6/7、HR/加速度/融合、RF/CNN、缺失与未知标签处理；独立于声音数据 |
| 软件闭环 | 公开 PSG 样例 → 参考与预测复核 → 波形/谱图/事件 CSV → 确认删除；真实聚合实验浏览 |
| 复现闭环 | 官方数据获取/准备说明，新机器真实收据绑定，CPU 自有 RF 训练与本地模型收据，新实验显式登记 |
| 交付 | Windows 安装启动、必要检查、真实截图、研究局限、答辩稿、Git 提交与远端比对 |

完整性依据流程、证据与边界；模型没有达到可靠个人事件定位能力的事实必须保留，不能为得到更漂亮的数字改测试集或挑选样例。跨硬件整套重建、跨种子稳定性和临床验证没有完成，不据此作声明。

## 不拿个人数据也能演示

1. 执行 `scripts/setup_app.ps1`、`scripts/start_app.ps1`，打开 `http://127.0.0.1:8766`。
2. 没有本地数据时，直接打开「实验比较」，浏览仓库自带的八组真实聚合报告与图；或生成明确标记的合成 Demo 检查界面。合成 Demo 不是研究成果。
3. 按 [安装指南](INSTALLATION.md)、[数据说明](DATASETS.md) 准备已批准的 PSG 十人数据后，首页「从公开研究样本开始」可载入两位验证集受试者各自的**固定前 120 秒**。不根据模型表现挑片段；不自动联网或读取任意服务器路径。
4. 每次载入重新核对官方原始摘要、当前特征来源/产物收据及 EDF/RML 时间对应，仅读 `Mic`；复制为 `private/app` 下的 float32 WAV，保持原 ADC 比例，不做响度归一化。卡片只检查文件在场，按钮可用不等于完整性已经验收。
5. 两分钟片段的 PSG 呼吸参考由 RML 裁剪而来，标为「PSG 参考」，与「模型预测」「用户标记」「合成 Demo」区分。跨边界参考带截取提示，参考不能被当成用户标记单独删除。没有目标参考的片段如实显示零条。
6. 选择本地自有 RF 并开始分析，检查波形、谱图和参考/预测，导出带来源的事件 CSV。片段用于定性复核，不在此重选阈值或计算正式测试分数。删除仅移除工作台副本及关联数据，公开原始 EDF/RML 不删除。

原始 EDF/RML 没有已核验时区，展示使用片段相对时间，不制造绝对时区。PSG-Audio 与 SleepAccel 是两组独立受试者与实验，不能为了“完整”而假配成同一晚的声音和心率。可穿戴研究在「实验比较」独立展示。

## 从自己的公开数据复现到桌面分析

先完成 [安装指南](INSTALLATION.md) 的数据审计、明确下载授权、官方校验与准备；SleepAccel 新机器收据另见 [可迁移复现](PORTABLE_REPRODUCTION.md)。以下命令不会下载数据，CPU 数值线程不超过二、RF 单 worker，无需 CUDA。

```powershell
# 查看计划；默认不训练、不写模型
.venv\Scripts\python.exe -m scripts.train.app_audio_rf --run-name my-public-audio-rf
# 从固定的、已准备并校验来源的 PSG 十人 corpus 实际训练
.venv\Scripts\python.exe -m scripts.train.app_audio_rf --run-name my-public-audio-rf --execute
# 默认只检查本次经典 run 的聚合指标；再显式登记到实验页
.venv\Scripts\python.exe -m scripts.register_experiment --run-name my-public-audio-rf
.venv\Scripts\python.exe -m scripts.register_experiment --run-name my-public-audio-rf --execute
```

训练会拒绝已有 run/模型/收据，不能覆盖历史成果。新 RF 产生本次源码、依赖、metrics 和权重摘要绑定的私有收据，桌面读取为 `local_rf_my-public-audio-rf`。CLI 不接受上传/导入已有未知 pickle；只有本次入口真正训练的 RF 才能走此登记路径。校验失败则不可分析，不使用假预测补位。

`register_experiment` 支持现有经典训练入口产生的 PSG 十人、SleepAccel 三十一人与历史三人聚合报告，只将白名单聚合指标/分组人数/参数快照放入 `private/local-experiments`。原始身份、输入路径和逐窗结果不进入该快照；不会修改冻结报告。模型登记和实验登记各自显式完成；只登记报告不会让未知模型获得执行权限。CNN 仍按深度协议和冻结的自有模型收据核验，不支持任意外部权重导入。

原始数据、特征、完整 runs、模型与私有收据保持忽略。干净克隆不附送这些文件；“只依靠公开数据”指数据来源公开且流程完整，不表示自动下载或 Git 附带数 GB 文件。

## 可选 DLC

- 本人手机音频：单人探索、导入与复核；没有 PSG 真值时不报告个人准确率。
- Android 采集端：源码与已签名 debug APK 已构建，JVM/合成桌面互通已验；真实麦克风、锁屏和整夜仍未验收。
- 个人手表当前不可得，不等待；舍友不纳入当前范围。
- 长上下文模型、额外数据与跨设备扩展继续按明确研究问题、资源窗口和数据授权实施。

这些扩展保留各自验收状态，均不阻塞公开数据主项目交付。真实执行收据与本阶段检查见 [公开主线验收](PUBLIC_CORE_ACCEPTANCE.md)。
