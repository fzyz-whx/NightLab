# NightLab 五分钟讲解与答辩备忘

依据：PROJECT_SPEC.md、EXPERIMENTS.md、PHASE2_ACCEPTANCE.md、WEARABLE31_RESULTS.md。下述数字来自现有真实报告；演示数据与个人数据不参与正式准确率计算。

## 0:00–0:45：问题与定位

大家好，NightLab 是一个本地优先的夜间声音与可穿戴睡眠时序研究工作台。我关心两个问题：第一，背景干扰下，声音事件检测还能否可靠工作；第二，消费级设备的心率和加速度能否预测未见受试者的公开睡眠阶段标注。两条模型分别训练、分别评价，在界面里共同查看时间轴。并列展示不代表已经做了跨模态融合，也不输出医疗诊断或没有依据的健康分数。

## 0:45–1:35：数据与防泄漏

项目先做数据文件、许可、标签和时间对齐审计，再做模型。声音使用 PSG-Audio 已批准的十位受试者各一小时，按六、二、二分组。可穿戴最终使用 SleepAccel 1.0.0 的三十一人，按十八、六、七分为训练、验证、测试。旧三人仅进入新的训练集，不能把旧试点分数当成新模型进步幅度。标准化、缺失填补等统计只由训练集拟合，检查点按验证集选择。测试集不用于反复挑阈值。原始数据和模型权重保存在本地忽略目录，公开仓库保留代码、来源与聚合结果。

## 1:35–2:30：真实基线与负面结果

声音比较统计特征随机森林与轻量频谱 CNN。RF 的测试窗口 Macro-F1 为 0.5960，原始 CNN 为 0.5438；但窗口分数并不代表事件定位可靠。连续事件采用固定阈值及一对一 IoU 至少 0.5 的匹配：RF 事件 F1 只有 0.1156，每小时误报 40.5 次，CNN 则为 0.0637 和 35 次。漏检和误报都很严重，因此我没有将它包装成可用的呼吸暂停检测产品。

可穿戴三十一人实验中，心率、加速度、融合 RF 的测试 Macro-F1 分别是 0.23836、0.27118、0.31161，融合最好；对应 CNN 是 0.20877、0.21391、0.24739，全部低于相应 RF。多数类基线为 0.12849。七个测试受试者仍然很少，不能凭六千多个相关 epoch 宣称大样本人群有效。

## 2:30–3:30：抗噪实验为何需要完整对照

我用合成白噪声和工频干扰，设置负五、零、五、十 dB，比较原始参考、滤波、加噪、加噪并滤波。这里的参考录音本身有自然背景，不是无噪的生理信号。原始 RF 与 CNN 在白噪声四档均不检出事件；零误报是因为全判背景，不能称抗噪成功。噪声增强 CNN 在不滤波白噪声零、五、十 dB 下分别匹配到三、六、一个参考事件，但总参考有八十二个，改善非常有限。

为了避免训练量翻倍被误认为噪声贡献，我加入等样本量的原始重复控制。原始、重复控制、增强 CNN 在未缩放测试上的事件 F1 分别为 0.0637、0.1304、0.0970。增强窗口分数有所恢复，却没有全面胜过控制；早停还造成实际更新步数不同，这个限制也一起报告。

## 3:30–4:25：软件现场演示

打开本地工作台，先加载标为合成的演示记录，展示时间轴、波形、局部声谱图与播放。合成事件明确是 demo，不是模型预测。再导入一段拥有使用权的 WAV，并用通用 CSV 或 JSON 附加心率、阶段；缺失值保持缺失。手动标注与模型预测分开记录，可导出事件 CSV。模型未准备时显示不可用，不假装已有推理。最后演示确认删除：清除本地记录文件及关联 SQLite 条目。安装、数据准备与启动分开，启动不会自动下载数据和权重。

现场如果没有可用的真实模型文件，就仅演示导入和媒体路径，并打开聚合实验报告讲解已有离线研究结果；不点击无法完成的推理后再声称成功。

## 4:25–5:00：复现与下一步

项目固定数据划分、随机种子、参数、来源摘要和环境锁；同种子独立重训、保存加载后的概率与权重均做了核验。它证明本机流程可重复，不是跨硬件保证或跨 seed 统计。当前主要价值是完整且诚实的研究和工程流程。下一步应预先登记新的验证选择协议，研究更长时间上下文、外部设备与跨 seed 稳定性；个人手表没有 PSG 金标准，不用来报告正式准确率。

## 常见问题

**为什么 CNN 不如随机森林？** 当前样本、表示、训练方式均有限；RF 用统计特征而 CNN 用时序/频谱输入，不能把差异完全归因于网络深度。保留负面结果比只展示最好的模型更能支持后续研究。

**为什么不直接报 accuracy？** 三十一人测试多数类 accuracy 就有 0.47325，但其 Macro-F1 只有 0.12849。项目用含五类的 Macro-F1、平衡准确率和每类结果揭示不平衡。

**预测的是鼾声还是呼吸暂停？** 训练目标依据公开参考事件标签及固定窗口规则，并非逐段听音标注。当前软件中的输出是研究预测，不能视为医学诊断或证明声学机制。

**为什么不能把两小时的多种噪声条件算更多样本？** 它们来自同两位受试者的相同录音变体，相关性很强，只是受控条件，不是新的人或独立观测。

**你做了什么融合？** 可穿戴实验中的融合指心率与加速度联合输入；声音和可穿戴在界面上的并列显示不等于联合训练。

**许可是什么？** 自编代码采用 MIT；数据保留各自 CC BY 或 ODC-By 许可与引用要求，不随软件重新授权。SleepAccel 需保留 Walch、NSRR 引用及资助致谢，详见 DATASETS.md。

**现在已经完成医学或真实个人设备验证了吗？** 没有。当前证据为公开数据上的固定划分研究、本机复现和单独的软件验收；个人录音与手表探索不能替代临床或外部验证。
