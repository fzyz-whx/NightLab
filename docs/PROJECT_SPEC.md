# NightLab：Codex 项目总任务书

> **给 Codex 的完整背景说明。**
> 不得假设你知道此前聊天。本文件是需求的唯一来源。\
> **目标：**
> 完成《医学人工智能导论》课程项目，并形成适合保研夏令营展示的个人 AI
> 软件工程作品。\
> **项目定位：**
> 一个本地优先、界面简洁、算法真实、实验可复现的夜间声音与可穿戴睡眠时序研究工作台。不是医疗诊断产品，也不是单纯的睡眠评分
> App。

## 1. 项目背景与目标

开发者是计算机/人工智能专业本科生，医学知识不是主要优势。项目应以经典
AI、深度学习、信号处理、时序建模和软件工程为核心，医学睡眠场景是应用对象。

核心想法来自三类数据： 1.
**公开睡眠声音数据**：训练和评价声音事件检测模型，研究环境噪声、去噪和时序上下文的影响。
2.
**公开可穿戴数据**：训练独立的睡眠阶段/时序模型，研究心率、加速度等信号是否能预测公开标注的睡眠阶段。
3.
**个人数据**：开发者自己的手机夜间声音和可导出的手表数据形成一份个人夜间记录，用于探索性分析与软件演示。室友可能在明确知情同意后提供额外声音片段，主要用于筛选真实背景干扰、噪声增强和探索个体差异。

这些资源角色不同，**不要求所有数据同时进入同一个模型**。声音模型和可穿戴模型应先独立训练、独立评价；产品可以在同一时间轴上展示两个模型的结果。只有数据真正同步、任务与标签兼容时，才探索联合模型。

### 1.1 项目优先级

1.  研究问题和实验可信度；
2.  公开数据、标签和许可可行；
3.  自己实现并验证经典 ML/DL 模型；
4.  工程质量、可复现和隐私；
5.  简洁、专业、好看的 UI；
6.  可选扩展。

### 1.2 不做什么

-   不诊断睡眠呼吸暂停，不提供医疗建议，不宣称医疗级准确率。
-   不复制 vivo/小米已有的睡眠评分和睡眠报告。
-   不只是给现成模型套 UI。
-   不把四个人的声音强行合成四路输入；声源分离不是 MVP 的必要功能。
-   不依赖 vivo 或小米专有 API 才能运行；通用 CSV/JSON 导入必须可用。
-   不在启动时自动下载大型数据或模型。
-   不将原始个人录音、健康数据、凭据或未经授权的数据上传到 GitHub。
-   不编造标签、准确率、下载成功、Git 提交或推送状态。

## 2. 初始研究问题与数据门槛

### 2.1 声音主问题

> 在夜间录音存在背景噪声和设备差异时，如何更可靠地定位睡眠呼吸相关声音事件？传统滤波、噪声增强训练或轻量深度学习方法能否改善下游事件检测，而不损伤目标事件？

任务粒度必须由真实数据标签决定： - 有事件起止时间：可以做事件定位； -
只有窗口/呼吸周期标签：做相应粒度的分类； -
只有整夜/患者级标签：不能声称做出了事件级检测器，应更换数据或缩小研究任务。

### 2.2 可穿戴主问题

> 能否利用消费级可穿戴设备的心率与加速度时序，训练一个可复现的睡眠阶段预测基线，并评估它在未见受试者上的表现？

睡眠阶段标签必须来自公开数据中的参考标注，不是厂商自有评分。个人手表数据没有
PSG 金标准，只能用于探索和可视化，不可用来报告正式准确率。

### 2.3 先做数据审计

第一项工作必须是建立
`docs/DATA_AUDIT.md`，检查数据文件、字段、标签、时间戳、许可、下载大小、校验和与引用。不能凭论文摘要猜测字段。发现不匹配时，记录证据并提出替代方案，不能悄悄假定数据符合需要。

## 3. 数据集清单与选择

以下公开页面提供了当前可核实的信息。Codex
必须在实际使用时重新检查版本、文件列表和许可，并将证据写入
`docs/DATASETS.md`。

### 3.1 声音主候选：2025 多模态睡眠呼吸暂停数据集

-   DOI/官方入口：https://doi.org/10.57760/sciencedb.19070
-   论文：https://www.nature.com/articles/s41597-025-05583-8
-   托管：Science Data Bank，优先尝试这一国内托管入口。
-   论文描述：50 名患者、超过 400
    小时；包含智能手机录音、数字录音设备录音、睡眠结构、心率、血氧及事件标注；36
    名患者还有呼吸气流数据。
-   优点：手机录音场景接近个人采集，并有同步生理信息可供核查。
-   必须确认：数据集使用许可/协议、实际下载大小、事件标签类型、标注时间粒度、录音与标签同步方式、公开使用和再分发限制。

### 3.2 声音备用：PSG-Audio

-   论文：https://www.nature.com/articles/s41597-021-00977-w
-   数据 DOI：https://doi.org/10.11922/sciencedb.00345
-   元数据：https://doi.org/10.6084/m9.figshare.14611581
-   论文描述：212 份 PSG
    记录，含同步的气管接触麦克风与环境麦克风录音；专家标注睡眠阶段和呼吸暂停事件。
-   优点：适合事件时间定位和比较不同麦克风采集条件。
-   限制：专业麦克风环境不等同于普通手机枕边录音。
-   必须确认：数据文件、事件标签具体存放位置、许可、下载大小。

声音主数据若许可不清、下载不可行或没有可用的时间标签，转向 PSG-Audio
或将任务降级；必须记录理由。

### 3.3 可穿戴主数据：SleepAccel

-   官方页面：https://sleepdata.org/datasets/sleepaccel
-   文件页：https://sleepdata.org/datasets/sleepaccel/files
-   官方文档：https://github.com/nsrr/sleepaccel-documentation
-   页面描述：ZIP 约 563 MB，31 名受试者；包含 Apple Watch
    加速度、心率、步数，以及 PSG
    标注的睡眠阶段；官方页面说明开放访问且无额外访问/使用限制。
-   适用任务：以心率、三轴加速度（步数在有意义时加入）预测公开标注的睡眠阶段。
-   必须核验：标签编码、缺失值、时间戳单位、文件格式、引用与许可。

### 3.4 可穿戴可选扩展：BIDSleep 1.0.1

-   官方页面：https://physionet.org/content/bidsleep-dataset/1.0.1/
-   DOI：https://doi.org/10.13026/rees-1092
-   页面描述：47 名参与者、253 个夜晚；Apple Watch
    瞬时心率与三轴加速度，对齐 Dreem 2 EEG 参考睡眠阶段。每夜包含
    `motion.csv`、`hr.csv` 和 `labels.mat`。
-   压缩约 5.9 GB，解压约 27.9 GB；许可为 Open Data Commons Attribution
    License v1.0。
-   **默认不下载全量 BIDSleep。** 先用 SleepAccel
    完成最小流程；仅当需要多夜泛化测试、磁盘与网络预算允许且用户确认后，才下载必要子集。官方页面提供
    `SHA256SUMS.txt`，必须使用并核对。

### 3.5 选择原则

-   优先从官方 Science Data Bank 下载声音数据。
-   首先下载 README、元数据、文件清单和小样本，不要一开始下载完整数据。
-   可穿戴先用 SleepAccel；BIDSleep 是可选扩展。
-   不使用来源不明的网盘或未经核验的 Gitee/GitHub 重上传版本。
-   公开论文不自动代表数据文件可任意再分发；许可未确认前，不下载或发布数据。
-   原始数据不进入
    Git；只提交脚本、manifest、字段说明、审计报告和可公开的合成 demo
    数据。

## 4. 下载与网络流量要求

用户希望尽量减少代理/VPN
流量。所有数据获取必须先审计，再下载样本，最后才是用户确认后的完整数据。

### 4.1 下载流程

实现 `scripts/datasets/`，至少支持： -
`audit`：读取元数据和本地文件状态； -
`plan`：显示来源、版本、许可、预计大小和校验方式； -
`sample`：在官方允许时下载最小样本； -
`download --dataset <id> --confirm-large-download`：明确确认后下载； -
`verify`：检查大小、目录结构和 SHA-256； -
`prepare`：转换成内部统一格式。

默认只运行
dry-run；禁止应用启动时自动下载。所有大文件下载支持断点续传、磁盘空间检查和失败后续传。

### 4.2 国内源优先

1.  Science Data Bank 的官方国内托管入口优先。
2.  普通 Python 包可先尝试清华 PyPI 镜像
    `https://pypi.tuna.tsinghua.edu.cn/simple`，失败时回退官方 PyPI。
3.  PyTorch 必须先检测 Python、驱动和 CUDA 环境，再按 PyTorch
    官方安装选择器匹配版本；不要盲装不兼容 CUDA 包。
4.  SleepAccel/PhysioNet
    先检查官方文件级下载；只有找到明确由高校/科研机构托管、版本匹配且可校验的镜像时才使用。否则使用官方源并断点续传。
5.  Android Gradle 依赖仅在后续开发录音 App
    时处理，使用官方或可信国内镜像。
6.  不允许为省流量使用来源不明的模型权重或数据包。
7.  若官方未提供 checksum，下载后计算本地
    SHA-256，并标记为本地校验值，不能冒充官方校验值。
8.  下载前显示文件大小，超过 500 MB 的数据默认必须等待用户明确确认。

## 5. 声音模型与抗噪实验

### 5.1 基线与模型

至少实现： 1. 传统基线：RMS、谱质心、log-mel 等特征 + Random Forest 或
SVM； 2. 轻量深度学习：log-mel spectrogram + CNN； 3.
可选时序模型：CNN-GRU 或 TCN，用来比较局部窗口与上下文； 4.
抗噪对照：原始音频、传统滤波/谱门限、噪声增强训练；深度学习去噪只在有合理训练与评价方案时加入。

不要求使用大型预训练模型。参数、采样率、窗口长度、hop
size、随机种子与模型版本必须记录。

### 5.2 室友录音的正确用途

-   只有获得所有可能被录到的参与者明确知情同意后，才可采集和使用。
-   室友录音可能包含鼾声、说话声和其他事件，不能整段都标为噪声。
-   手动审核并筛选合适的背景片段；含可识别谈话或个人声音的片段默认不用作噪声素材，除非相关人员明确同意该用途。
-   将筛选后的真实环境干扰片段与公开数据中有可靠标签的目标音频混合，构造已知
    SNR 的可控实验。可从 -5、0、5、10 dB 起步，检查削波并保持标签不变。
-   先按受试者划分
    train/validation/test，再做混合，防止同一原始目标片段的变体泄漏到不同集合。
-   真实宿舍录音用于探索性评估；有已知干净参考的合成混合用于定量评估，结果分开报告。
-   若没有配对干净/噪声参考，不得声称完成了监督式去噪训练。
-   去噪是否成功，主要看下游事件检测是否改善，不只是音频听起来是否悦耳。

### 5.3 指标

-   分类：Precision、Recall、F1、Macro-F1、类别不平衡时优先看 PR-AUC。
-   有事件起止时间时：事件级
    Precision/Recall/F1、每小时误报数、起止定位误差。
-   抗噪：不同 SNR
    下的性能曲线、相对干净条件的下降、不同噪声类型的影响。
-   有配对参考时可报告 SNR improvement / SI-SDR
    improvement，同时必须报告下游检测表现。
-   不得只凭听感或单一信噪比指标声称医学事件识别变好。

## 6. 可穿戴睡眠时序模型

### 6.1 任务

使用 SleepAccel
的心率与三轴加速度，预测数据集支持的睡眠阶段。先解析标签编码和时间对齐，不得假设数字标签的含义。Unknown/无效标签必须按文档化规则处理。

### 6.2 模型

至少实现： 1. 多数类/简单规则基线； 2. Random Forest 或类似经典 ML； 3.
轻量 1D-CNN 或 GRU； 4. 消融：只用心率、只用加速度、两者融合。

### 6.3 划分和指标

-   按受试者分组划分，使用 GroupKFold 或 subject-wise
    train/validation/test；禁止随机切分 epoch。
-   指标：Macro-F1、balanced accuracy、各阶段 F1、混淆矩阵；可补充
    Cohen's kappa。
-   记录类别不平衡、缺失值、对齐/重采样策略和随机种子。
-   不用总体 accuracy 作为唯一指标。
-   BIDSleep 是可选扩展；在用户确认前不下载全量。
-   用户个人手表数据没有 PSG 金标准，不用于正式准确率报告。
-   不假设 vivo WATCH GT 2 或小米有可直接使用的开放 API；优先实现
    CSV/JSON 通用导入。若只能拿到整夜汇总，就只展示汇总。

## 7. 两条路线的关系

声音模型和可穿戴模型先独立训练、独立评价。产品可以将结果放在同一晚的时间轴上，但并列展示不等于多模态融合。

只有在同一夜的音频和可穿戴数据确实同步、标签兼容、有明确研究假设和足够样本时，才做融合模型，并比较： -
声音单模态； - 可穿戴单模态； - 融合模型。

不满足这些条件时，只能称为探索性时间关联，不得宣称融合提高了准确率。

## 8. 产品与界面

NightLab
是一个**本地优先的个人研究工具**。普通用户打开后不应被模型结构、指标、训练参数淹没。

### 页面 A：夜间记录（默认首页）

-   导入 WAV 音频，可选导入睡眠阶段/心率 CSV 或 JSON；
-   显示夜间时间轴、波形、可用的睡眠阶段/心率和检测事件；
-   缺失数据明确显示，不用虚构数据补齐；
-   不生成没有可靠依据的健康分数。

### 页面 B：事件检查

-   音频播放器、波形、声谱图、时间轴联动；
-   点击事件后播放局部片段并显示预测类别、置信度和模型版本；
-   无真实标签时只能显示"模型预测"，不能显示"真实事件"或"诊断结果"；
-   支持导出事件 CSV；手动标签要标明是用户标签。

### 页面 C：实验比较（高级功能，按需打开）

-   选择预设实验：基线、去噪、噪声增强、时序模型、可穿戴模型；
-   展示真实运行产生的指标、混淆矩阵、性能曲线和失败案例；
-   显示数据版本、划分方案、参数、随机种子、模型版本；
-   高级参数可折叠，不让普通使用流程复杂化；
-   Demo 数据必须明确标注 synthetic/demo，不能冒充真实研究结果。

### 视觉风格

-   简洁、专业、克制；避免满屏渐变、霓虹、无意义 KPI 和复杂控制台首页。
-   统一字体、间距、图表单位、图例、时间刻度和空状态。
-   中文为主，专业缩写附简短解释。
-   界面精致但功能数量要克制；研究复杂度放在后端和按需打开的页面中。

## 10. 隐私与数据安全

-   所有可能被录到的参与者必须明确知情同意；任何人拒绝时不得采集其声音。
-   夜间音频可能包含谈话和敏感健康信息，默认仅本地存储。
-   原始录音、手表数据、个人元数据、私有标注、日志和模型权重加入
    `.gitignore`。
-   GitHub 只提交代码、文档、许可/引用、合成 demo
    和已获准公开的非敏感结果。
-   提供个人记录删除功能并要求确认。
-   默认不上传云端、不启用遥测。
-   `docs/PRIVACY.md` 说明数据流、存储、删除方式与风险。
-   项目不能用于诊断；所有 UI 和 README 明确说明研究用途。

## 11. 实验规范与可复现性

-   按受试者分组划分训练/验证/测试；禁止同一人的相邻音频窗或睡眠 epoch
    跨集合。
-   归一化、特征选择、阈值和超参数只从训练/验证集确定。
-   噪声混合在分组划分后进行，防止数据泄漏。
-   每次实验记录数据版本、匿名受试者
    ID、随机种子、模型参数、依赖版本、运行时间和指标。
-   图表从实验记录自动生成，不手动修改指标。
-   报告负面结果和失败案例，不隐藏不利结果。
-   `docs/EXPERIMENTS.md`
    包含问题/假设、数据、划分、模型、指标、结果、消融、失败案例和局限。

## 12. Git/GitHub 真实开发过程

用户明确要求 Git 记录真实的从零开发过程，并尽可能每个实质性提交后同步
GitHub。

1.  先检查当前目录、Git
    状态、remote、分支与已有文件；不得覆盖用户已有工作。
2.  如果没有 Git 仓库，初始化并使用 `main`；如果已有仓库，先理解现状。
3.  检查 `gh` 是否安装和登录。不要索取、打印或写入 token/password。
4.  小步提交，每个有意义的阶段先测试再
    commit/push。提交信息真实反映变更，例如
    `docs: audit public datasets`、`feat(audio): add baseline detector`、`feat(wearable): add subject-wise evaluation`。
5.  每次推送后检查远端分支和 commit hash；推送失败时不得声称成功。
6.  禁止伪造历史、一次性假装完成全部开发、未经允许 force push。
7.  GitHub 仓库若不存在且已有授权，可以创建
    `NightLab`；若需要用户授权/确认，先请求。
8.  每个里程碑更新 README 和
    `docs/PROJECT_LOG.md`，写明功能、测试、commit
    hash、推送状态和未解决问题。
9.  不提交数据、模型、凭据或个人录音。

## 14. 阶段与完成标准

### Phase 0：仓库 + 数据审计

交付：本文件入库、`DATA_AUDIT.md`、`DATASETS.md`、许可/引用清单、下载计划、初始
Git 提交。
完成标准：确认实际文件、标签粒度、时间戳、许可、大小和下载路径；尚未下载大数据。

### Phase 1：两个模型的可复现基线

交付：声音数据解析、可穿戴数据解析、传统 ML
基线、受试者级划分、评估脚本和真实图表。
完成标准：至少一个声音基线与一个可穿戴基线真实运行；无受试者泄漏；解析与指标有测试。

### Phase 2：深度学习和抗噪实验

交付：声音 CNN、可穿戴
1D-CNN/GRU、噪声混合、去噪/增强对照、实验记录和错误分析。
完成标准：完成基线对比、消融与失败案例；结果可复现。

### Phase 3：研究软件

交付：本地前后端、夜间记录、事件检查、实验比较、CSV/JSON
导入、SQLite、合成 Demo、Windows 启动说明。
完成标准：普通用户可以导入示例数据、浏览时间轴和事件；高级实验不干扰普通流程；无死按钮和虚构结果。

### Phase 4：个人数据 + 可选 Android 录音

交付：个人音频/手表数据导入适配、删除功能；核心稳定后再做 Kotlin Android
录音端（前台录音服务、权限说明、WAV 导出、时间/设备元数据）。
完成标准：个人声音与可用手表记录能显示在同一晚时间轴；没有手表数据时声音功能仍正常；个人数据不会进入
Git。

### Phase 5：交付打磨

交付：测试、真实截图、README、数据引用、实验结果、面试讲解提纲、GitHub
真实历史。
完成标准：新环境可按文档运行；所有未通过测试有说明；仓库无个人数据/凭据/未经许可的大文件。

## 15. 自动化测试最低要求

-   运行测试后记录结果；不允许默默忽略失败。

## 16. 依赖和环境

-   Python 依赖写入 `pyproject.toml` 并锁定可复现版本；前端提交
