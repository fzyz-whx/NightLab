# 声音数据实际文件审计

核查日期：2026-10-24。结论：主候选 V5 的时间对齐存在实测冲突，暂停依赖其事件时间训练。尚未下载任何完整夜间 WAV，以下音频信息仅来自官方 HTTP Range 返回的前 65,536 字节。

## 来源与完整性

- 官方记录：https://www.scidb.cn/en/detail?dataSetId=7b5f1df9c3d4435baa0ff2dbecf487d9 ，V5、CC BY 4.0。
- 官方前端公开脚本 `https://www.scidb.cn/_nuxt/9b26054.js` 的 `genDownloadUrl` 明确生成 `https://china.scidb.cn/download?fileId=...`；该国内原始下载入口实际返回原始文件名、精确 Content-Length，支持 Range。
- `downloadFileMole` 是预览接口，可能转换格式。01 的阶段 CSV 在此入口实际变成 8,601 字节 ZIP/XLSX，官方 MD5 不匹配，已被工具拒绝。不能用预览接口下载训练原始数据。
- 通过官方 `childrenFileListByPath` 元数据接口遍历 Data/01 至 Data/50，取得 380 个文件条目，合计 56,765,543,989 字节；加根目录作者代码 19,379 字节共 381 文件。清单见 `data/catalogs/sciencedb-19070-v5.json`。这里只下载元数据，没有下载这些信号文件。
- 01_annotation.json（15,798字节）、02_annotation.json（95,315字节）、01_sleep_stage.csv（24,218字节）均与官方 MD5 匹配；作者 osa_data_eng.py（19,379字节）MD5匹配，只阅读未执行。原始文件均留在 gitignored data/raw。
- 本地 SHA-256：01 JSON `25bed7efd887dfeb45c968ff53c8737b426e3d8c70ee77dc926d33109b05b934`；02 JSON `bf6734af043a9fba9eede6c6e5516c85ed2944e3aafa89d57ef4ec21d1ae057a`。它们不是官方 SHA-256。

## 实际字段与时间

JSON 顶层为 record_start、awake_intervals、events。实际事件起点键拼成 **evnet_start**，另有 event_type、event_duration、sleep_stage。起点为可超过86,400的连续秒值，不能简单取模24小时。01包含86个事件（hypo85、osa1）；02包含574个事件（hypo160、osa414）。这些是参考生理事件，不是已经听音逐段核对的鼾声标签。

01的23段awake_intervals中有一段重复；3个事件的阶段标为W。保留原始记录并报告，不能为了得到更好指标随意删掉。

01睡眠阶段CSV列名实际为 position (epoch)、absolute position (hh:mm:ss.ms)、Default Staging Set ("stage")；1174行，首行22:39:34，末行08:26:04。标签W438/N1 87/N2 403/N3 104/R141/空白1。CSV首个时刻比JSON record_start（75454，即20:57:34）晚6120秒，须有独立音频起点证据才能对齐。

## 无法直接进入事件训练的证据

官方手机WAV头均为PCM、8 kHz、单声道、16 bit。RIFF声明文件大小与官方完整文件元数据大小一致，但尚未对完整音频执行MD5。

| 样本 | 头部推导时长（秒） | 事件减record_start后的最后终点（秒） | 在该假设下越界事件 |
|---|---:|---:|---:|
| 01手机 | 22257.92 | 29772.9 | 19/86 |
| 02手机 | 21299.16 | 36759.8 | 255/574 |

01全部事件跨度23338.9秒，比音频声明时长还长1080.98秒；02跨度35572.8秒，比音频声明时长长14273.64秒。因此只调整一个常量偏移也无法把所有事件放进对应音频。01另两份录音器WAV头时长为11781.568、15844.16秒，不能据此认定它们解决问题。

作者脚本load_single_data说明record_start用于对齐；读取阶段时直接减r_start，小时小于12时加24。已读代码未提供可解释上述跨度差异的裁剪/分段映射。现有证据不足以判断是文件裁剪、版本问题、标注范围不同还是其他原因，不能宣称数据损坏或自行修复时间轴。

复现：`python -B -m scripts.datasets.inspect_sciencedb --subject 01`（或02）。命令先校验完整JSON的官方MD5，再读取局部WAV头，冲突返回1。完整音频是否校验始终明确为false。

## 冲突、备选和推荐方案

原计划直接以此主数据训练事件定位器。实际文件不支持直接采用论文描述的相减方案；也不支持按越界比例截标签或凭总时长缩放标签。

1. 保留本数据，先取得原始同步/裁剪说明和正确文件对应表，再复核完整样本。最贴近手机场景，但当前不能可靠进入事件训练。
2. 审核原任务书备用PSG-Audio，若EDF和RML能在实际样本中对齐，采用其声音基线；须说明专业麦克风与手机的域差异。
3. 若两者都不具备可靠事件时间标签，另行明确缩小任务粒度，不能把整夜标签冒充事件标签。

推荐先推进方案2的元数据和小标注审计，同时将主候选冻结为待解决。未正式替换训练数据；没有训练或精度结果。
