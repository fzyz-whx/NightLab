# Android 本人声音采集端：范围与验收计划

2026-10-26。用户当前个人数据范围只有本人声音，暂无手表数据、不纳入舍友。此文件保留采集协议。当前已实现源工程并真实构建/签名核验首版APK，真机录音尚未验收；使用和构建见../android/README.md。

## 首版目的

形成“本人手机采集 → 本地WAV/时间元信息导出 → NightLab桌面导入 → 播放/人工复核与研究模型探索”的可检验链路。公开数据继续承担正式训练/评价；手机录音没有PSG金标准，不自动产生真实呼吸事件、睡眠阶段或健康评分。

## 首版功能

- 用户明确点击开始/停止，仅在有权采集且不涉及未同意他人的场景录音；不自动开机录音或静默启动。
- Kotlin Android客户端；前台麦克风服务和可见录音通知，界面显示实际状态/时长/文件大小，通知可停止。
- 流式写入PCM16单声道WAV，优先16kHz；若设备不支持则验证可用采样率并记录实际值，不写假header或悄悄声称16k。桌面本来接受8–96kHz。
- 长录音按约1小时分片，保留session/分片顺序、真实起止时间与时区、sample_rate/channels/frames、实际设备/音源、结束/中断状态；停止后修正WAV长度并校验。
- 原始录音只在App私有存储，不申请联网或云上传。用户主动导出WAV与不含额外账号/定位数据的JSON元信息，并可确认删除。
- 检查空间、权限拒绝、录音中断和进程重启；不将中断文件标为完整，也不把缺口补为实测静音。
- 先支持开始/停止和完整导出。暂停/续录若会产生时间缺口，应另建分片并明确记录，不能把不连续样本标成连续整夜。

16kHz、16bit、mono的PCM正文约115.2MB/小时，8小时约921.6MB，另有WAV头；这是格式预算，不是实测手机耗电/空间成绩。若回退48kHz则数据量约三倍，界面/元信息必须反映实际格式。

## 平台约束依据

[Android前台服务类型官方文档](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone)要求麦克风前台服务声明相应类型/权限，并先获得RECORD_AUDIO运行时授权。由用户在可见界面启动，不依赖后台或开机接收器自动开始。[运行时权限文档](https://developer.android.com/training/permissions/requesting)要求检查授权和妥善处理拒绝；不因用户拒绝而伪造正在录音。

使用[AudioRecord官方API](https://developer.android.com/reference/android/media/AudioRecord)获取真实PCM，再以有界缓冲写WAV；构建版本/依赖在实际准备构建环境时核实并锁定，不在这里猜最新SDK。前台服务不自动证明厂商锁屏/省电策略下整夜不中断，须实测。

## 分层验收

1. 源码与格式：固定构建版本、WAV头/长度/帧/分片及异常停止检查；合成PCM导出可由桌面已有soundfile/media验证。只能声明文件和软件逻辑通过。
2. 构建：在隔离的项目工具环境真实生成APK，记录版本/SHA/构建日志；没有构建成功不交付假APK。
3. 真机短录：权限拒绝/允许、可见通知、开始/停止、回听、WAV/JSON导出、桌面导入，实际格式/时间一致。
4. 真机锁屏：先20–30分钟，检查前后台切换、完整帧数、声音可听/时间连续、通知停止、异常中断标识和文件可恢复情况。
5. 本人夜间：前面通过后再录一夜，核对分片/时区/总样本时长/中断与文件大小。只有此时才声明该手机上的夜间采集链已验收；不等于医学准确率或其他手机可靠性。
